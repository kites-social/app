# PMSA-10 page-by-page visual audit

## Scope and reading the results

The mockup runner produced 102 reference renders: 51 named screens in light and dark themes (`pmsa10-mockup-screens/`). The Expo app has existing route families and stateful screens, not 51 one-to-one pages. This matrix maps every mockup reference to the existing route/state and records whether any visible difference is an implementation issue, actual account/backend state, or a deliberately unimplemented mockup-only screen.

The live app was inspected on the attached Pixel 8a through the host Metro. Both themes were exercised across the main screen families. The final screenshots for the last visual corrections are in `screenshots/light|dark/`; earlier route captures are retained as audit evidence but are not all recaptured after the final shared-component edits. In particular, markets, search, settings, profile, notifications, and settings preferences have current light/dark evidence. No trade, purchase, sign-out, wallet unlock, or preference mutation was performed for visual coverage.

## Visual fixes confirmed in the live app

- Theme-aware Kites green primary / blue secondary tokens and light/dark semantic surfaces are applied through existing navigation/theme infrastructure.
- Shared feed, notification, grouped-list, form, settings, profile, market-widget and navigation components were visually checked against the reference system; existing controls and route behavior were preserved.
- Grouped-list sections now have high-contrast theme-aware headings in dark mode, inset 56dp rows, green icon wells and consistent spacing.
- Profile tabs are narrower to fit real labels better; real extra tabs remain horizontally scrollable.
- Prediction-market outcomes now sit on a bordered, rounded theme surface while regular social posts stay flat.
- Account switcher is framed as a single settings card, without changing sign-out/add-account behavior.
- Profile accounts without a banner use the Kites gradient fallback; the profile app bar no longer duplicates a back control.

## Remaining differences / review notes

- The HTML uses Inter and a desktop/iPhone-like frame; Android renders native system typography/status/navigation chrome. No font assets are currently vendored in this app, so Android uses its platform sans font. This is the clearest remaining global typography/frame difference.
- Mockup content is illustrative. Live posts, profile completeness, timestamps, market names/prices, wallet state, and settings values are not expected to match.
- Search suggestions/trending data and event market data are currently empty, loading, or unavailable from the live backend. Those are data states, not visual implementation omissions.
- Routes 49–50 have no Expo equivalent and remain intentionally absent under the no-new-pages constraint. Route 51 exists but cannot be truthfully verified without completing a purchase.
- Human review is still required for final product/design acceptance.
